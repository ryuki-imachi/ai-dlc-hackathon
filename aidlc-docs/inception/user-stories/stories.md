### 段階構造（2 段階版）

| 段階 | 体験 | 実装範囲 |

## 1. 段階 1: 最初から自律

### US-1.1: Google カレンダー / Gmail 連携

**As a** 鈴木健太として、
**I want** Google カレンダーと Gmail をマカセルに連携して、
**So that** AI が私の予定とメールを把握し、自律的にサボリ判定と代行を実行できるようにしたい。

| 項目 | 値 |
|---|---|
| Stage | 1 |
| Scope | MVP |
| Priority | Must |

**Acceptance Criteria**:
- **AC-1.1.1**: Given マカセルにログインしている、When 「Google 連携」ボタンを押す、Then OAuth 同意画面に遷移し、許可後にカレンダー読み取り / イベント更新 / Gmail 送信スコープが付与される
- **AC-1.1.2**: Given カレンダー / Gmail 連携済み、When AI が情報取得を試みる、Then 当日の予定一覧と関連メールが取得できる
- **AC-1.1.3**: Given OAuth が失敗または権限取消、When AI が取得を試みる、Then 自律実行は停止され、ユーザーに再連携を促す画面が表示される

---

### US-1.2: AI による自律的なサボリ判定と代行実行

**As a** 鈴木健太として、
**I want** AI が毎日カレンダー / Gmail を読み取って「サボれること」を判定し、**私の承認を取らずに** 代行アクション（依頼 / 断り / 延期）を送信してほしい、
**So that** 自分で判断する重荷も、依頼文を書く労力も、誰かに頼む心理的ハードルも消える。

| 項目 | 値 |
|---|---|
| Stage | 1 |
| Scope | MVP |
| Priority | Must |
| 注意 | この US は「承認なし自律実行」の核。設計上、最も重要 |

**Acceptance Criteria**:
- **AC-1.2.1**: Given カレンダー連携済み、When 日次トリガまたは初回ログイン、Then AI が「サボってよい予定」を 3〜5 件抽出し、それぞれに対して 3 タイプ（**依頼 / 断り / 延期**）のいずれかを **自動選択**する
- **AC-1.2.2**: Given 代行アクションが選択された、When 自律実行モードが有効、Then AI は **ユーザー承認なし** で Gmail / Google Calendar API を叩いて代行を送信する（ハッカソンスコープではモック宛先のみ）
- **AC-1.2.3**: Given 「依頼」タイプが選ばれた、When AI が依頼メールを送る、Then 依頼先候補（同僚 / 上司 / チームメンバー）に対し、依頼理由を含む丁寧な依頼メールが自動送信される
- **AC-1.2.4**: Given 自律実行の対象外（明示リスト外、または重要案件の判定）、When AI が判定不能、Then **何もしない**（送信しない）。実行可能な範囲のみが処理対象
- **AC-1.2.5**: Given 後押しメッセージ（タレカツ C 対応）、When 各代行に「サボっていい根拠」が短く付与される、Then 「この会議、議事録だけで十分」「先方は急ぎではありません」などの理由付きでログに記録される

---

### US-1.3: 代行ログの事後確認

**As a** 鈴木健太として、
**I want** AI が「いつ・誰に・何を依頼 / 断り / 延期したか」を後から確認できるようにしたい、
**So that** ブッチに見えないよう自分の代わりに何が起きたかを最低限把握できる（タレカツ A 対応）。

| 項目 | 値 |
|---|---|
| Stage | 1 |
| Scope | MVP |
| Priority | Must |

**Acceptance Criteria**:
- **AC-1.3.1**: Given 代行アクションが実行された、When DynamoDB に書き込まれる、Then 実行内容（日時 / タイプ / 宛先 / 件名 / 本文の要約 / 結果）が記録される
- **AC-1.3.2**: Given ログが蓄積されている、When ユーザーがログ画面を開く、Then 過去 30 日のログが時系列で表示される（タイプ別フィルタあり）
- **AC-1.3.3**: Given ログ表示画面、When 30 日経過した記録、Then DynamoDB TTL で自動削除される

---

### US-1.4: 音声 / テキストでの追加指示（任意）

**As a** 鈴木健太として、
**I want** 音声で「明日の朝会、いらない」と独り言を言うか、テキストで指示することで、AI に追加のヒントを伝えたい、
**So that** AI の自律判断をさらに私の意向に近づけられる（必須ではない、AI は発話なしでも動く）。

| 項目 | 値 |
|---|---|
| Stage | 1 |
| Scope | MVP |
| Priority | Should |
| 入力モード | 音声（メイン） / テキスト（サブ） |

**Acceptance Criteria**:
- **AC-1.4.1**: Given アプリで音声入力が有効、When ユーザーが「これサボる」「明日の朝会、いらない」など発話、Then AI がその意図を当日の自律実行判定に反映する
- **AC-1.4.2**: Given テキスト入力欄、When ユーザーが同様の意図を入力して送信、Then 音声経路と同じく AI が判定に反映する
- **AC-1.4.3**: Given 発話 / 入力なし、When 日次トリガが起動、Then **AI は独立して自律実行する**（追加指示は必須ではない）

---

### US-1.5: 暴走防止セーフガードと緊急停止

**As a** 鈴木健太として、
**I want** AI が暴走したとき / 想定外の代行をしたときに止められる手段が欲しい、
**So that** 完全自律でも一定の安心感を持って使える。

| 項目 | 値 |
|---|---|
| Stage | 1 |
| Scope | MVP |
| Priority | Must |

**Acceptance Criteria**:
- **AC-1.5.1**: Given 自律実行の対象、When AI が判定する、Then **明示ホワイトリスト**（特定イベント種類 / 特定送信先）の範囲内のみ実行可能。範囲外は何もしない
- **AC-1.5.2**: Given 設定画面の「マカセル一時停止」スイッチ、When ON にする、Then 自律実行が即座に止まる（再開は同スイッチを OFF）
- **AC-1.5.3**: Given ハッカソンスコープ、When AI が代行を実行、Then 実宛先には送信せず、**モック宛先（demo@example.com 等）のみ** に送信する

---

## 2. 段階 2: 戻れない境地

### US-2.1: ログ表示の自動隠蔽（決勝向け）

**As a** 鈴木健太として、
**I want** 成功した代行のログが時間経過で視界から消えていってほしい、
**So that** AI に任せていることすら意識しなくなり、本当に「戻れない」境地に入る。

| 項目 | 値 |
|---|---|
| Stage | 2 |
| Scope | 決勝 |
| Priority | Should |

**Acceptance Criteria**:
- **AC-2.1.1**: Given 代行が成功してから N 日経過、When ログ画面を開く、Then その項目はデフォルトでは表示されない（「過去のログを表示」ボタンを押せば見える）
- **AC-2.1.2**: Given デフォルト画面、When ユーザーが見る、Then 「最近 AI が動いた件数: N 件」のサマリのみ表示される（中身を意識しなくて済む）

---

### US-2.2: 30 日後の利用者ストーリー演出（決勝向け、デモ用）

**As a** 鈴木健太として、
**I want** マカセル を 30 日使った後の自分の状態（TODO を見ない / AI が裏で動いている）を可視化されたい、
**So that** 自分がどれだけマカセルに依存しているかを実感できる。

| 項目 | 値 |
|---|---|
| Stage | 2 |
| Scope | 決勝 |
| Priority | Could |

**Acceptance Criteria**:
- **AC-2.2.1**: Given マカセルを利用開始から 30 日経過、When ダッシュボードを開く、Then 「ログを開かなかった日数 / AI 代行送信数 / 依頼を引き受けてくれた人」などのサマリが表示される
- **AC-2.2.2**: Given デモシナリオ用の固定データ、When プレゼンテーション中にダッシュボードを表示、Then 「30 日後の鈴木健太」のリアルなビジュアルが提示できる
- **AC-2.2.3**: 本ストーリーは演出用、ロジックの正確性より見せ方の品質を優先する

## 4. 旧版（3 段階構造）からの差分

2026-05-09 の設計変更で削除されたストーリー:

| 旧 ID | 旧タイトル | 削除理由 |
|---|---|---|
| 旧 US-1.2 | サボってよいリストの生成と表示 | 「リスト表示 → 人間判断」が不要になり、新 US-1.2（自律実行）に統合 |
| 旧 US-1.3 | 音声 / テキストでのサボリ宣言（核） | 「ユーザー宣言 → AI 動作」のフローを廃止、新 US-1.4（任意の追加指示）に格下げ |
| 旧 US-2.1 | 代行アクションの下書き生成 | 下書き生成は内部処理化、ユーザーには見せない |
| 旧 US-2.2 | 音声 / テキスト承認による代行実行 | 承認ステップを廃止 |
| 旧 US-2.3 | Gmail / Google カレンダー経由の代行実行 | 新 US-1.2 の AC に吸収 |
| 旧 US-2.4 | 代行ログの確認 | 新 US-1.3 に改番 |
| 旧 US-3.1 | 自律実行モード | 「最初から自律」のため、モード切替自体が不要 |
| 旧 US-3.2 | 30 日後の利用者ストーリー演出 | 新 US-2.2 に改番 |

新規追加:
- 新 US-1.5（セーフガードと緊急停止）— 完全自律のため、暴走対策をユーザー価値として明示

## 6. 残論点

- 自律実行のホワイトリスト（イベント種類 / 送信先）の具体定義は Functional Design で
- 「明示ホワイトリスト」と「重要案件判定」の境界線は Application Design で詳細化
- 30 日後ストーリー（US-2.2）の演出データは決勝直前のリハーサル準備時に用意
- AI が「依頼先」を選ぶロジックは Functional Design で（カレンダー参加者 / Gmail 連絡先 から推定）
